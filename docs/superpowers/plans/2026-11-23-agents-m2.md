# Agents M2 (CLI and engine for AI agent sessions) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A developer runs AI coding agents (claude, codex, agy, or any tool described by a config file) as named, resumable conversations bound to tmux panes and to tasks (branch, optional worktree). `cairn agents`, `cairn task`, `cairn event` and `cairn status` cover start, resume after reboot, live state, finish with a quality-gated record, search and import. All of it is testable without real AI tools.

**Architecture:** Adapters are TOML (`tools/*.toml`) rendered into argv by a pure templating function; no tool name appears in engine code. Conversation records live in an append-only JSONL store with one record per line (last write per id wins, periodic compaction) and per-conversation `flock` locks. Live state is a fold over per-conversation events posted by hooks through `cairn event` (no daemon in M2; the file is the bus). Agent panes are ordinary reconciler panes whose argv is `cairn agents pane <id>`, a wrapper that resumes the tool lazily. Tasks drive plain `git` through `execx.Runner`. The search index is a redacted, incrementally built text file set, no cgo and no SQLite.

**Tech Stack:** Go (existing module `github.com/mrqwer/cairn`, no new dependencies), `go-toml/v2`, `cobra`, existing `internal/{xdg,fsx,execx,workspace,reconcile,tmux,history,events,ui,doctor,config}`; tests use `execx.FakeRunner`, fake tool scripts written into `t.TempDir()`, temp git repos, and real tmux on isolated sockets (skipped when tmux or git is absent).

**Spec:** `docs/specs/engine-agents.md` §9.1–9.9, §10, §11, R1–R3, R6–R10 (milestones M2, M3, M4 and M5 of R1 delivered together as this plan). Principles: `docs/principles.md`. UX reference: Tasks view of `docs/ui-prototype.html`.

## Global Constraints

- Public repo: no author-specific names, paths or project names in code, docs, fixtures or tests (use `/home/u/...`, project ids `demo`, `api`, tool names `claude`, `codex`, `agy`, `fake`).
- XDG paths via `xdg.Dirs`: adapters in `<Config>/tools/*.toml` (built-ins embedded, user files override by `name`), profiles in `<Config>/profiles.toml`, records in `<State>/agents/`, hook files in `<State>/agents/hooks/`, index in `<State>/agents/index/` (0600). Tasks are desired state: `<Config>/tasks/<id>.toml`, written through `internal/history` so they are undoable (R2).
- Deviation from spec §5/R2 (ruling, consistent with the M1 history ruling): `state.db` is `<State>/agents/conversations.jsonl`, no SQLite and no cgo. The file is append-only; a reader takes the last line per `id`; `Compact` rewrites atomically under the store lock. A truncated trailing line is ignored, never an error.
- tmux only through `tmux.Client` / `execx.Runner`. **Every test that starts tmux uses an isolated socket `cairn-test-<pid>-<n>` and `t.Cleanup` kills that server; no test may touch the default server** (reuse the guard in `internal/cli` real-tmux tests; add one to any new package that needs it).
- Argv, never shell strings: templates produce `[]string`; `{profile_args...}` splices zero or more elements; a placeholder inside an element is replaced as one string (spaces and quotes preserved). Unknown placeholders are a load error.
- Hooks are passed per process (settings file / `-c` overrides); the user's own tool settings are never read for writing or edited.
- Irreversible operations (merge, push, PR, native delete, transcript delete) always require confirmation or an explicit flag and are labelled "not undoable" (R3). Worktree removal never loses uncommitted or unpushed work without `--force` plus a printed loss summary.
- Redaction runs before anything reaches the index; the index and hook files are 0600.
- Never kill or rewrite panes not carrying a `@cairn_p` marker. Never write inside a user's repo except the task branch/worktree it created.
- Output uses `internal/ui` styling for terminals, plain text on pipes; `--json` where listed.
- Commit messages describe the change only — no AI attribution. Do not push.

## Review Focus

1. **A conversation is never resumed in two panes**, including two concurrent `resume` processes — Task 3.
2. **After a simulated reboot** (`cairn up` on empty tmux) agent panes exist and show names, the tool starts only on first attach, and starts via `resume`, not `start` — Task 4.
3. **Hook injection cannot damage user settings**, and a hook that fails or never fires degrades to `observed` state, never blocks the tool — Task 5.
4. **`task finish` never removes a worktree with uncommitted or unpushed work** without `--force`, and merge/PR are never implied — Task 7.
5. **The quality gate and the redactor are strict where it matters:** secrets never reach the index; fluff and long records never reach the knowledge hand-off — Tasks 8 and 10.
6. **Tolerant parsing:** a garbage or future-versioned transcript is skipped and reported, never crashes `import`/`find` — Task 10.
